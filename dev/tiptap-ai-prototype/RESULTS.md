# Результаты проверки совместимости

Дата повторного прогона: 9 ноября 2026 года. Среда стенда: Node 22.19.0. По данным нового `results/report.json`, фактически установлены и проверены Tiptap 3.33.0 и публичный `@tiptap/ai-toolkit` 0.4.1. Использованы исходники ветки `chore-update-tiptap`.

Первый прогон на 3.32.0 обнаружил потерю QMS ID. В текущем прогоне проверено исправление общего mark. Отдельный lock-файл стенда пересоздан npm: прежние записи версий 3.33.0 содержали несоответствующие контрольные суммы. Установка по новому lock-файлу прошла с включённой проверкой целостности. Стенд теперь проверяет фактические версии перед выполнением и не принимает запуск на старой установленной версии за проверку нового манифеста.

## Вывод

Публичный SDK работает без браузера с настоящим общим `ServerKit` TraceX. Получение контекста схемы и добавление описаний собственных расширений работоспособны. Проверка подтверждает локальную совместимость этих возможностей; платный движок AI-редактирования и готовность миграции рабочих документов ещё не проверены.

Обнаруженное несоответствие QMS mark исправлено: сервер и клиент используют одно общее определение атрибута `node-uuid`, правил перекрытия и поведения на границе текста. Стандартный `ServerKit` сохраняет идентификатор комментария с Toolkit и без него. Клиент добавляет к общему mark команды и обработчики интерфейса.

## Исправленная потеря идентификатора

QMS mark в исходном тестовом документе:

```json
{ "type": "node-uuid", "attrs": { "node-uuid": "prototype-qms-comment" } }
```

До исправления чтение и обратная запись JSON статической серверной схемой давали:

```json
{ "type": "node-uuid" }
```

Потеря воспроизводилась без расширения AI Toolkit. Серверный mark не объявлял атрибут и, в отличие от клиентского, исключал перекрывающиеся marks одного типа.

Теперь [общий mark](../../foundations/core/packages/text/src/marks/qmsInlineCommentMark.ts) объявляет атрибут, допускает перекрывающиеся комментарии и не распространяет их на ввод за границей отмеченного фрагмента. [Клиентский mark](../../plugins/text-editor-resources/src/components/extension/qms/qmsInlineCommentMark.ts) расширяет это определение, сохраняя свои команды и обработчики. В новом прогоне JSON после преобразования сохраняет исходный ID. Это подтверждает согласованность данного QMS mark; полное совпадение всех расширений клиента и сервера по-прежнему не утверждается.

Успешного `node.check()` недостаточно для доказательства сохранности: чтение JSON уже могло удалить отсутствующие в схеме атрибуты.

## Проверки прикладного кода

- Все 8 наборов Jest пакета `@hcengineering/text` прошли: 79 тестов, включая 3 регрессионных теста сохранности QMS ID, перекрывающихся комментариев и ввода рядом с отметкой.
- Четыре целевых набора Jest редактора прошли: 25 тестов. Они включают новые проверки совпадения QMS-схем, клиентских команд, обработчика клика и переноса комментариев через HTML, а также ранее проблемные embed, Mermaid и table snapshot.
- Native TypeScript validation пакетов `text` и `text-editor-resources` прошла. Проверка редактора до изменений также прошла без генерации файлов: присланные ошибки миграции уже были исправлены в текущих исходниках и установленных зависимостях.
- Диагностика изменённых TypeScript-файлов не показала ошибок или предупреждений. Проверки синтаксиса `run.cjs`, `run.sh` и `git diff --check` прошли.

## Что даёт получение контекста

- Сохранённый контекст содержит настоящую структурную схему узлов и marks.
- Исходный компактный JSON занимал 8 164 байта. После добавления четырёх описаний и схем атрибутов тестового документа размер составил 9 637 байт.
- Исходный список смысловых описаний не объясняет собственные типы TraceX `reference`, `inline-comment`, `node-uuid` и некоторые другие. Их структурные определения при этом присутствуют. Явные метаданные добавляют объяснение выбранных типов; права и сохранность данных нужно обеспечивать отдельно.
- Описание на самом расширении отдельно проверено на настоящем клиентском QMS mark, без передачи через параметр `customNodes`.

## Что ещё не проверено

По выбранному условию исследован только публичный SDK, без платного доступа. Не выполнялись авторизованные вызовы API Tiptap, генерация LLM, работа закрытого клиентского Toolkit, изменения рабочего пространства, синхронизация с работающим collaborator, обработка одновременных правок и проверка полного браузерного редактора. Публичный пакет предоставляет контекст и работу с `_hash`; платного движка выполнения tools в нём нет.

## Что делать теперь

Ближайшие автоматические шаги выполнены: прежние ошибки проверки типов не воспроизводятся, QMS mark согласован, стенд повторно прошёл на 3.33.0.

1. **Вручную проверить QMS в приложении.** Создать несколько комментариев на одном фрагменте, сохранить и повторно открыть документ, проверить переход к комментарию и ввод рядом с отмеченным текстом.
2. **После получения доступа проверить настоящий Toolkit.** Сначала выполнить заранее заданную правку искусственного документа через `--live`, затем проверить агентный сценарий.
3. **Проверить сохранение через collaborator при одновременных изменениях.** Локальная совместимость схемы не подтверждает согласование параллельных правок.

Результат позволяет использовать `getEditorContext()` как основу описания схемы. Готовность полного AI-редактирования рабочих документов ещё требует проверок API и интеграции.

## Как воспроизвести и проверить

Из корня репозитория выполните `bash dev/tiptap-ai-prototype/run.sh`. Откройте созданный `results/report.json`, два документа после чтения и записи и три файла контекста SDK. Отчёт содержит хеши исходников, позволяющие различать запуски на меняющейся ветке.

Сборки, форматирование и операции Docker не запускались. Зависимости проектов Rush для этой работы не менялись; переустановлены только отдельные зависимости стенда. Изменения прикладного кода ограничены общим QMS mark, его публичным экспортом, клиентским расширением и регрессионными тестами. Проверка типов двух затронутых пакетов не является проверкой всего монорепозитория.
